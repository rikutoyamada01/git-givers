# Appendix B-3: The AI & You (Collaboration Guidelines)

At GitGivers, we don't fear AI; we hold the reins.
We encourage the use of LLMs (GitHub Copilot, ChatGPT, Claude) to accelerate development, but we maintain strict standards on *responsibility*.

## 1. The Core Philosophy
**"The Pilot is Responsible for the Plane."**

Autopilot guides the plane, but the Pilot lands it.
-   If you copy-paste code from ChatGPT and it breaks production, **you** broke production, not ChatGPT.
-   You cannot blame the AI. You signed off on the commit.

## 2. Usage Rules

### 2.1 The "Do Not Copy-Paste Blindly" Rule
AI hallucinates. It invents libraries that don't exist. It writes insecure code.
-   **Understand every line**: If you don't know what a line does, don't commit it. Ask the AI to explain it, or read the docs.
-   **Security Check**: AI loves to put API keys in code or ignore SQL injection vulnerabilities. Be vigilant.

### 2.2 Transparency
We value honesty.
-   **PR Disclosure**: If a significant chunk (e.g., >50% of a complex algorithm) was generated by AI, add a note in your PR.
    > "Note: The regex logic for email parsing was generated by Claude 3.5 Sonnet."
-   *Why?* It alerts reviewers to check for "AI-isms" (subtle but confident errors).

### 2.3 Legal & Ethics
-   **No Private Data**: Never paste private keys, user data, or proprietary trade secrets into a public LLM chat interface.
-   **License Compatibility**: Ensure the code AI gives you doesn't look like it was ripped verbatim from a GPL repository (rare, but possible). GitGivers is MIT; we must stay compliant.

## 3. Best Practices for AI Prompting

Want better code? Ask better questions.

### 3.1 Provide Context
AI has no Short-Term Memory of your file structure unless you give it.
-   *Bad*: "Write a user component."
-   *Good*: "I am building a Next.js 14 App Router project using Tailwind and Prisma. Create a `UserProfile` server component that takes a `userId`, fetches data using Prisma, and displays the `karma` field. Handle the 'user not found' case."

### 3.2 Iterative Refinement
Don't accept the first draft.
1.  **Generate**: Get the base code.
2.  **Critique**: "This uses `useEffect` for data fetching, but we are in a Server Component. Rewrite it to fetch directly."
3.  **Polish**: "Add proper TypeScript interfaces (PascalCase) and JSDoc comments."

## 4. The "Turing Test" for Code
Before submitting AI code, ask yourself:
*"If I had to explain this code to a junior developer on a whiteboard, could I do it?"*
If the answer is **No**, you are not allowed to push it.
